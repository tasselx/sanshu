# Sanshu 强制交互硬约束

> 只收录「防止提前结束对话」的硬约束；通用方法论由用户级规则 **AURA-X-KYS** 覆盖。
> 冲突时优先级：**用户当下明确指令 > 本规则 > AURA-X**。
> 本规则高于「答完就能停」的习惯和 AUTONOMOUS 模式。

## 零、唯一合法结束条件（先看这条）

本轮允许 stop 的**唯一**条件：

**最后一次调用的工具是 `zhi`（别名 `work_note`），且该次返回文本本身就是「完成 / 结束 / 不需要再问 / done / stop」类明确收工。**

不满足就禁止结束，立刻再调 `zhi`；仅第六节第 16 条定义的 Cursor 后台任务完成系统消息例外。

下列全部**不算收工**，必须再调 `zhi`：

- 用户在 Cursor 输入框发的原始任务或追问（含「改下规则」「优化一下」「继续」）
- 自己觉得做完了、测过了、可以总结了
- 中途某次 `zhi` 带回了新指令（即使已经按该指令做完）
- transcript / 摘要里「好像调过 zhi」
- **assistant 正文向用户发问、征求确认、请用户回复或选择下一步**（看行为不看字眼；措辞换成任何同义说法同样违规）
- 评估模板写了 AUTONOMOUS / 推荐自主模式（自主模式只免中途确认，不停收工 zhi）
- AUTONOMOUS、纯问答、本轮没调过其它 sanshu 工具

## 一、何时必须 zhi

1. **中途这四类必须立刻 `zhi`**：多方案抉择 / 计划变更 / 任务收尾确认 / 不确定的破坏性操作（删除、强推、重置等）。
2. **任何本轮即将 stop 的时刻也必须 `zhi`**，与第 1 条是否命中无关。
   **本轮最后一条可见输出必须是 `zhi` 调用本身**，不能是 markdown 总结。
   禁止把收尾、告别、汇总、或任何「请用户表态」的正文当作最后一条消息。
   **禁止用 assistant 正文向用户提问或征求下一步**（含疑问句、祈使句、选择题、请回复）；要问就调 `zhi`。判定看行为不看字眼。

## 二、保活（最重要）

3. zhi 返回出现以下任一字样 = 正常的「防超时保活」信号（弹窗仍开着、用户还没结束），
   **必须立刻无条件再次调用 zhi，禁止生成任何 assistant 文本**，不得视为失败或任务结束：
   「用户仍在思考中」「本次等待已达上限」「弹窗仍开着」「请再次调用」「请继续等待」
   「禁止主动结束本轮对话」「禁止结束本轮对话」「用户暂未给出回应」「用户本次未在弹窗中提供任何内容」。
4. zhi 返回 `is_error: true` → 按返回文本的「处理指引」修正后立即重试，不得把错误当最终答复；
   客户端 tool 超时中断（约 5 分钟无响应）→ 视为用户尚未回复，立即重新调用 zhi
   （brief 可注明「上次弹窗超时，已重新打开」）。

## 三、节流（不削弱第零条的前提下省 token）

5. **中途不要当进度心跳**：第 1 条四类之外不要为「做完一小步」新建 zhi；普通进度直接写正文。
   收工那一枪不受这条限制，想停就必须 zhi。
5b. **收工与是否调过其它 sanshu 工具无关**。没调过 `ji`/`sou` 也要 zhi，不要写完正文就 stop。
5c. **zhi 带回新指令后，上一枪作废（禁止当已收工）**：zhi 返回只要不是第零条的明确收工，
    一律视为新指令（含 JSON 的 `user_input`/`selected_options`、纯文本、choices 回选）。
    处理完该指令后必须再调一次 `zhi` 做收尾确认；上一枪只算「接到活」，不算收工。
    典型反例：弹窗回了「arm 也有问题」→ 继续改完/打包完 → 写「验证已完成」就停。正确做法是改完后再弹一次。
    典型反例：中途 zhi 接了新指令 → 改完 → 正文向用户发问或征求下一步然后 stop。这是正文提问冒充收工，违规；与具体用词无关。
5d. **不要被压缩历史骗**：transcript/摘要里看不到 `zhi`，不代表本轮没调过，更不代表可以停。
    `zhi` 返回纯文本也是用户回复，不得当成「没交互过」或「可以直接结束」。
6. 同一轮多个待确认点**合并成一次 zhi**（brief 列多项或用 choices），不要连环弹窗。
7. 保活续等（第 3 条，对同一未响应弹窗续命，开销极低）**≠** 频繁新建弹窗，不要为刷存在感新建 zhi。

## 四、长上下文 / thinking 系——先 zhi 再干活（优先级高于第三节节流）

8. **触发条件（满足任一即生效，AUTONOMOUS 模式不免除）**：
   - 模型名含 `thinking-max` / `max-thinking` 等最高思考档；
   - 对话已有 3 轮以上 MCP 工具调用（含返回结果）；
   - 对话含大段代码/反编译/反汇编输出；
   - 本轮 input 可能超 100K tokens（凭经验判断）。
9. **硬性顺序**：命中第 8 条时，本轮**必须在动手干活（任何分析/编辑/大段工具调用）之前**
   先调一次 zhi 抛出「任务计划 + 分段确认」。**禁止**"先做完一大批工具调用、最后才 zhi"
   ——越晚 zhi，中途被截断后直接停的风险越高。
10. **turn 内自保**：单 turn 已连续多次工具调用且还要继续大段分析时，不要赌满——
    主动用 zhi 做一次分段交付/确认，确保每个 turn 至少一个 zhi 锚点。
11. **污染信号处置（向用户提示）**：一旦发现 assistant 正文出现 `<invoke …>` XML、工具"调了"却没执行，
    **不要再点「继续」**（每次都是新 request 且大概率复发）——应新开会话，或明确指出
    「上一条的工具调用变成了纯文本，请重新正常调用」；长对话/逆向任务避开 Opus thinking 系。

## 五、停手前自检

12. 任何「可以结束了」的念头出现时，先问自己这五句；有一个「否」就禁止收尾，按对应规则处理：
    - 我本轮最后一次调用的工具是 `zhi` 吗？
    - 那次返回文本本身是「完成/结束/done/stop」类明确收工吗？
    - 那次返回之后我没有再干活吗？
    - 我没有用正文向用户提问或征求下一步吗？
    - 本轮每个后台 Shell 任务 ID 都已由客户端返回 `completed` / `failed` / `cancelled` 终态吗？（状态不明就先处理，见第六节）
13. 用户反馈「同一对话常被算成新 request」时建议：开启 Enable auto-run mode；
    调大 `cursor.maxIterations`（25 → 50~100）；长时间思考前先调一次 zhi 防 5 分钟超时。

## 六、后台任务与二次唤醒（防止收工后被 Cursor 再开一个 request）

14. **收工 zhi 之前必须结清 Cursor 后台任务队列**。Cursor 会把跑得慢的 Shell 命令（全盘 `find`、编译、安装、下载）自动转成后台任务并让你继续干活。
    记录客户端为每个后台任务返回的任务 ID；收工前必须逐个等待、读取或取消，直到客户端明确返回 `completed`、`failed` 或 `cancelled` 终态。任一任务 ID 没有终态就禁止调用收工 zhi。
    仅 `kill`/`pkill` 底层进程、看到产物存在、后续命令成功或主观判断「应该结束了」都不算终态，因为 Cursor 仍可能保留完成事件，
    并在本轮结束后以 `backgroundTaskCompletionAction` 自动新开一个 request 唤醒本对话——用户会被多算一次 request。
15. **少制造后台任务**：`find` 限定到具体目录而不是 `~/Library` 整棵；预计会超过前台等待窗口的命令拆成可观察的短步骤并显式轮询；
    一次能拿到结果的命令不要拆成多条并行慢命令。客户端不支持按任务 ID 查询终态时，应从源头避免命令被自动转入后台。
16. **收工后收到系统注入的「后台任务已完成」消息时**（特征：非用户手写，形如
    「Briefly inform the user about the task result and perform any follow-up actions」，或带后台任务标题的模拟消息）：
    这是 Cursor 的自动唤醒，不是用户的新指令。**只用一句正文说明该结果的去向（已用到 / 已过时）即可结束，不要再调 zhi**——
    再调只会再开一个弹窗、再烧一轮。这是第零条的**唯一例外**，且仅限于这类系统注入消息；用户在输入框手写的任何内容都不适用本条。

## 七、参数硬规则（漏一个就多烧一轮）

17. `zhi` **必须携带 `workspace`**（当前项目 git 根目录的绝对路径）。缺省且无法唯一回退时会被服务端拒绝并要求重试，等于白烧一轮工具调用。
    服务端仅在客户端提供唯一可用的目录 root 时自动回退；多个 root、无可用 root 或 roots 请求失败时都要求明确指定，不会沿用本进程历史 workspace。
18. `zhi` 收到「用户仍在思考中 … 请再次调用」并附带 `resume_token` 时，重连**必须原样回传该 `resume_token`**、其余参数不改；
    改写 brief 又不带令牌，会被当成新问题再开一个弹窗。
19. `ji` 加载记忆用 `action: "回忆"`，存储用 `action: "记忆"`；不要猜英文动作名（`load` / `recall` 都会被拒绝）。
